# Issue 83: 「プログラムから開く」や関連付け起動時にPDFファイルが開かれない問題の修正 - 実装計画

## 概要
エクスプローラーでPDFファイルを右クリックし、「プログラムから開く」またはダブルクリック（関連付け起動）によって PDF Binder を起動した際、渡されたファイルパス引数が無視され、初期状態（空ドキュメント）のままとなる不具合を修正する。

## 仕様合意事項（Grill-meヒアリング結果）
1. **多重起動・プロセス分離**: 既にアプリが起動している場合も、独立した別ウィンドウ・別プロセスとして新しく起動する（標準的なWindowsアプリの挙動）。
2. **複数ファイル指定時の挙動**: 渡されたPDFファイルごとに、それぞれ別プロセス（`Process.Start`）を起動して独立したウィンドウで開く。
3. **エラーハンドリング**: 指定ファイルが存在しない・破損している・無効な形式の場合は、エラー通知を表示し、アプリ自体は空の初期状態でそのまま開く。

## 設計と変更内容

### 1. `CommandLineArgsHelper`（`src/PDFBinder.App/Helpers/CommandLineArgsHelper.cs`）
WPF アプリケーションライフサイクルからロジックを分離し、単体テスト可能とする。
- コマンドライン引数（`string[] args`）のフィルタリングと正規化（引用符の除去、`.pdf` ファイル判定、フルパス化）。
- 先頭ファイル（現在のプロセスで開く対象）と、2つ目以降のファイル（別プロセスで起動する対象）への分割。

### 2. `App.xaml` & `App.xaml.cs`
- `App.xaml`: `StartupUri="MainWindow.xaml"` を削除。
- `App.xaml.cs`:
  - `OnStartup(StartupEventArgs e)` をオーバーライド。
  - `CommandLineArgsHelper` で引数を解析。
  - 複数ファイル指定時、2つ目以降のファイルを引数として自プロセスを `Process.Start` で起動。
  - `MainWindow` を生成して表示（`Show()`）。
  - 先頭ファイルが存在する場合、`MainViewModel.OpenDocumentAsync(filePath)` を非同期呼び出しして読み込み。
  - ファイル不存在やオープン時例外をキャッチし、ユーザーへエラー通知を表示の上、空ドキュメントで安全に起動継続。

### 3. 単体テスト（`tests/PDFBinder.Tests/CommandLineArgsHelperTests.cs`）
- 引数なし、単一PDF、複数PDF、PDF以外のファイル除外、引用符付きパス、無効文字等のテスト。

## 検証手順
1. `dotnet test`: 全テストが PASS すること。
2. `dotnet build`: ビルドが正常に完了すること。
3. 動作検証:
   - 引数なし起動
   - コマンドライン引数（単一PDF）起動
   - コマンドライン引数（存在しないファイル）起動
   - コマンドライン引数（複数PDF）起動
