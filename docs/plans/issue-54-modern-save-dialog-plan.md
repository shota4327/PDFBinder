# Issue #54 実装計画: 保存確認ダイアログのモダン化（インアプリ・オーバーレイ方式）

## 概要
PDFドキュメントに未保存の変更がある状態で、アプリ終了時（[X]ボタン・Alt+F4等）または別ファイル読み込み時に表示される「変更を保存しますか？」の確認ダイアログを、従来のクラシックなWin32 `MessageBox` から、**現在のアプリデザイン（ライト基調のFluentスタイル）に調和したモダンなインアプリ・モーダルオーバーレイ** へ刷新します。

---

## ユーザー合意事項（ヒアリングおよびフィードバック反映結果）
1. **対象ダイアログ**: 未保存変更の確認ダイアログ（終了時や別ファイル読込時の保存確認）
2. **UI形態**: メインウィンドウ内のインアプリ・オーバーレイ（半透明暗転背景＋中央カード型モーダルダイアログ）
3. **テーマ・デザイン**:
   - アプリの現在の外観に合わせた統一感のある**ライト基調のモダンFluentデザイン**
   - カード背景: 純白（`#FFFFFF`）、微細なボーダー（`#E2E8F0`）、柔らかなドロップシャドウ
   - タイトル・本文: Slate系ダークグレー（`#0F172A` / `#475569`）
   - ダークモード切り替え機構（レジストリ監視等）は不要とし、シンプルかつ堅牢な構成
4. **ボタン構成とラベル**:
   - **保存**: プライマリボタンスタイル（アクセントブルー `#2563EB`、白文字、角丸6px）
   - **保存しない**: セカンダリボタンスタイル（明確な破棄アクション）
   - **キャンセル**: セカンダリボタンスタイル（背景 `#F8FAFC`、枠線 `#CBD5E1`）
5. **インタラクション**:
   - 暗転領域（外側）クリックでは閉じない（安全重視・誤クリックによるデータ喪失防止）
   - Escキーで「キャンセル」
   - **Enterキーによる自動保存は行わない**（誤打鍵防止のため、明示的なクリックまたはTabキーによるフォーカス後の操作とする）
   - Tabキーによる自然なボタン間フォーカス移動

---

## 設計と変更内容

### 1. インアプリ確認ダイアログのViewModel設計
- `SaveConfirmationResult`: 既存の `Save`, `Discard`, `Cancel` 列挙型をそのまま使用。
- `MainViewModel`:
  - 確認ダイアログの表示状態・対象ファイル名を管理するプロパティを追加:
    - `IsSaveConfirmationVisible` (bool)
    - `SaveConfirmationFileName` (string)
  - 非同期でユーザーの選択を待機する仕組み（`TaskCompletionSource<SaveConfirmationResult>`）を導入。
  - ダイアログのアクションコマンド:
    - `ConfirmSaveCommand` (引数: `SaveConfirmationResult`)
      - ユーザーが「保存」「保存しない」「キャンセル」をクリックした際にオーバーレイを非表示（`IsSaveConfirmationVisible = false`）にし、待機中の `TaskCompletionSource` を完了させる。
  - 非同期確認メソッド `PromptSaveConfirmationAsync`:
    - 未保存変更がある場合にオーバーレイを表示し、ユーザーの選択結果を非同期で返却。
    - 単体テスト時は同期ハンドラやモックでオーバーライド可能な設計を維持。

### 2. メインウィンドウ（MainWindow.xaml）のオーバーレイUI配置
- `MainWindow.xaml` のルート `Grid` 最前面（最下行）に、`IsSaveConfirmationVisible` に連動する暗転レイヤーおよび中央カードを配置。
- **レイアウト構成**:
  - **Scrim（背景暗転）**: `Background="#500F172A"`（視覚的フォーカスを集めつつ、背後のPDFやUIが適度に透ける上品なトーン）。
  - **Card（ダイアログカード）**:
    - 幅: 440px
    - 背景: `#FFFFFF`
    - ボーダー: `#E2E8F0`（1px）
    - 角丸: `CornerRadius="12"`
    - ドロップシャドウ: `DropShadowEffect`（Color="#0F172A", BlurRadius=24, Opacity=0.18, ShadowDepth=6）
    - パディング: 24px
  - **コンテンツ**:
    - ヘッダーアイコン＆タイトル: 警告・確認を表すSegoe Fluentアイコン（`\uE7BA` 等）＋「変更内容を保存しますか？」
    - 本文: 「'{SaveConfirmationFileName}' に加えられた変更は、保存しないと破棄されます。」
    - アクションボタンバー: 右揃えで「保存」「保存しない」「キャンセル」を配置。
    - キーボード対応: Esc でキャンセル（Enterでの自動保存は行わない）。

### 3. ウィンドウ終了イベント（OnClosing）およびファイルオープンの非同期連携
- `MainWindow.xaml.cs` の `OnClosing`:
  - 未保存の変更がある場合、`e.Cancel = true` で即時クローズを一旦中断し、インアプリオーバーレイを表示。
  - 「保存」選択時: `SaveDocumentAsync()` を実行し、保存成功後に `_isClosingConfirmed = true; Close();`。
  - 「保存しない」選択時: `_isClosingConfirmed = true; Close();`。
  - 「キャンセル」選択時: オーバーレイを閉じてそのままアプリ操作に復帰。
- `MainViewModel.cs` の `OpenDocumentAsync`:
  - 変更がある場合は非同期にオーバーレイを表示し、結果に応じてオープンを続行または中断。

## 単体テストおよび検証計画

### 自動テスト
- `PDFBinder.Tests` の `MainViewModelTests.cs` にて以下を検証:
  - 未保存変更がある状態での保存確認要求でオーバーレイ表示フラグが立つこと。
  - 各ボタンコマンド（`Save`, `Discard`, `Cancel`）実行時に結果が正しく解決され、ダイアログが非表示になること。
  - 未保存変更がない場合は確認を行わずに処理が続行されること。
- `dotnet test` の全件実行（100% PASS）。
- `dotnet build` の正常完了確認。

### 手動検証
- **終了確認フロー**:
  1. PDF を開き、ページ回転などの編集を実施。
  2. ウィンドウ右上の [X] をクリック。
  3. メインウィンドウ内にライトテーマのモダンなインアプリ・オーバーレイが表示されることを確認。
  4. 「キャンセル」（または Esc キー）でダイアログが閉じ、編集状態が保持されることを確認。
  5. 再度 [X] を押し、「保存しない」でアプリが正常終了することを確認。
  6. 再度開いて編集し、[X] を押し、「保存」クリックで保存されて正常終了することを確認（Enterキーで勝手に保存されないことの確認含む）。
- **別ファイルオープン確認フロー**:
  1. 編集状態で「開く」ボタンを押した際、同様にインアプリ・オーバーレイが表示され、保存・破棄・キャンセルが意図通り機能することを確認。
