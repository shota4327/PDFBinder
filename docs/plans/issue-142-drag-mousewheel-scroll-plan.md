# Issue #142: グリッド表示でドラッグ中のマウスホイールスクロールおよびオートスクロール対応 実装計画

## 概要
PDFページのグリッド俯瞰ビューにおいて、ページドラッグ中（並び替えおよび外部PDF挿入）ならびに余白ドラッグによるラバーバンド矩形選択中に、マウスホイールによる縦スクロールおよび画面上下端への接近による自動スクロール（オートスクロール）を可能にします。これにより、多数のページが存在するPDF文書でもスムーズに長距離のページ移動や範囲選択が行えるようになります。

---

## 決定した設計方針（/grill-me 合意事項）
1. **対象スコープ**:
   - アプリ内ページのドラッグ＆ドロップ並び替え
   - 外部PDFファイルのドラッグ＆ドロップ挿入
   - 余白ドラッグによる「ラバーバンド矩形選択」
2. **マウスホイールスクロール挙動**:
   - ドラッグ操作中は Ctrl キーが押されていてもズーム操作を抑止し、通常の縦スクロールとして処理。
   - スクロール発生時、物理的なマウス位置に基づき挿入バー（青い縦インジケーター）またはラバーバンド矩形選択範囲をリアルタイムに再計算・更新。
3. **オートスクロール（自動スクロール）挙動**:
   - `GridScrollViewer` の上端・下端から 40px の領域にカーソルが進入した際にタイマー駆動でスクロール。
   - 端に近づくほど速度が上がる可変速度制御。
   - ドラッグ終了（Drop / Cancel / マウスアップ）時に確実にタイマーを停止・クリーンアップ。

---

## 技術アプローチと設計

### 1. OLEドラッグ中のマウスホイール検知
- WPF の `DragDrop.DoDragDrop` 実行中（OLE モーダルループ中）は通常の WPF `PreviewMouseWheel` イベントが発生しないため、以下の方式を組み合わせます:
  - ドラッグ開始時（`StartDrag`）およびドラッグオーバー中において、Windows メッセージフィルタ `ComponentDispatcher.ThreadFilterMessage`（または `HwndSource` フック）を登録して `WM_MOUSEWHEEL` (0x020A) を直接検知。
  - ホイール回転の `delta`（`GET_WHEEL_DELTA_WPARAM`）を取得し、`GridScrollViewer.ScrollToVerticalOffset` によりスムーズにスクロール。
  - スクロール実行後、直ちに `UpdateInsertionIndicator` を呼び出してドロップ先インジケーターを追従。
  - ドラッグ終了時（`EndDrag`）にメッセージフィルタを解除。

### 2. オートスクロール管理
- 単一責任の原則（SRP）およびメソッド行数制限（30〜50行）に従い、オートスクロールの判定・タイマー制御を `AutoScroller` クラス（ヘルパー）または GridView 内の独立した管理メソッド群として設計。
- 判定条件:
  - マウスの Y 座標が `GridScrollViewer` の上端 40px 以内の場合: 上方向スクロール（端に近いほど高速）。
  - マウスの Y 座標が `GridScrollViewer` の下端 40px 以内の場合: 下方向スクロール（端に近いほど高速）。
  - それ以外: スクロール停止。
- タイマー（`DispatcherTimer`）の間隔: 約 20ms（50fps）。

### 3. ラバーバンド選択中のスクロール連動
- ラバーバンド選択ドラッグ（`OnGridPreviewMouseMove`）時:
  - マウス移動時にオートスクロール判定を実施。
  - 通常の `OnGridPreviewMouseWheel` でもラバーバンド選択中であれば選択領域の更新とスクロールをシームレスに連動。
  - マウスアップ（`OnGridPreviewMouseLeftButtonUp`）時にオートスクロールタイマーを停止。
