# Issue #147 検証報告: バージョン管理・リリース運用ルールの修正（方式①への統一）

## 概要
`GEMINI.md` 内に記載されていたバージョン管理・リリース運用ルールにおいて、PRマージ後に `master` ブランチで直接コミットを行う記述となっていた矛盾を解消し、Issue駆動開発の大原則（`master` への直接コミット完全排除）に適合するよう「機能PR内で事前にバージョンおよびCHANGELOGを更新・確定する方式（方式①）」へ改定しました。

また、直前の `master` 上の直接コミット（`8379ce9`）は正常にロールバック完了しており、`master` がマージコミット `a97f8a4` を指すクリーンな状態であることを確認しています。

---

## 主な改定内容

### 1. プロジェクト開発規約の改定 (`GEMINI.md`)
- **`master` ブランチへの直接コミットを例外なく完全禁止**:
  - バージョン更新およびCHANGELOG更新も必ず各Issueの作業ブランチ（機能PR内）で実施し、PRレビューを経てマージするよう明記。
- **PR作成時の自律的インクリメント＆CHANGELOG更新（方式①）**:
  - 作業ブランチにおいて、加えた変更内容に応じて `Directory.Build.props` のバージョンを自律インクリメント（新機能: マイナー `0.X.0`、不具合修正・改善・ドキュメント: パッチ `0.X.Y`）。
  - 作業ブランチにおいて、`CHANGELOG.md` に新バージョンセクション（`## [X.Y.Z] - YYYY-MM-DD`）を確定・記述し、最上部に新たな空の `## [Unreleased]` を配置。
  - PRの差分（diff）でバージョン番号と変更履歴の事前レビューを可能とする。
- **マージ後の運用フロー**:
  - PR通常マージ後、`git checkout master`、`git pull origin master`、`git fetch --prune` を実行してローカルを最新化。
  - **`master` 上ではコミットを一切行わず**、最新化されたマージコミットに対して直ちに対応するGitタグ（`vX.Y.Z`）を作成・プッシュ。
  - 続いて配布バイナリ発行スクリプト（`build.ps1`）を実行する。

### 2. 基本設計書の同期 (`docs/basic_design.md`)
- セクション 9（バージョン管理およびリリース運用仕様）を方式①に同期・更新。

### 3. CHANGELOG ドキュメントの確定・統合 (`CHANGELOG.md`)
- PR #146 マージ直後に `[Unreleased]` に置かれていた Issue #145 の内容、および本Issue #147 のルール整備を `## [0.1.0] - 2026-09-22` セクションに統合・確定し、最上部に空の `## [Unreleased]` を再配置。
