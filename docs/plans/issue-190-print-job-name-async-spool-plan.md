# 実装計画: Issue #190 印刷ジョブ名へのファイル名反映・非同期スプール送信および終了待機

## 1. 概要
- **対象Issue**: #190（印刷ジョブ名にファイル名を入れる / 印刷完了直前のフリーズ調査および解消）
- **目的**:
  1. 印刷ジョブ名に「ファイル名（拡張子なし） - PDFBinder」を自動反映し、Windows印刷キューでの識別性を向上させる。
  2. 印刷完了直前にUIが数秒間フリーズする問題を、バックグラウンドSTAスレッドによる非同期スプール送信およびプレビューダイアログの即時終了により完全解消する。
  3. 送信中はメインウィンドウのステータスバーに「プリンターへ送信中...」を表示し、完了時は「印刷データを送信しました」を約3秒間表示する。複数印刷時は順次キューイングして並行受付を可能とする。
  4. 印刷送信に失敗した場合は、既存のエラー・警告ダイアログ（`ShowErrorDialog`）を表示してユーザーに通知する。
  5. 送信完了前にアプリを終了しようとした場合、アプリ内オーバーレイダイアログで印刷完了を待機し、完了後に自動終了する。また、終了を取り消して通常のアプリ操作へ戻す「キャンセル」機能を提供する。

---

## 2. 要件と設計仕様

### 2.1 印刷ジョブ名フォーマット
- 規則: `{ファイル名（拡張子なし）} - PDFBinder`
- 例:
  - `sample.pdf` → `sample - PDFBinder`
  - `document.2024.pdf` → `document.2024 - PDFBinder`
  - 未保存ファイル（`名称未設定.pdf` / `名称未設定.png` / 空文字） → `名称未設定 - PDFBinder`

### 2.2 印刷プロセスの2フェーズ化とフリーズ解消
1. **フェーズ1（シート画像生成フェーズ）**:
   - 印刷プレビューモーダル内で実行（現状のUIを維持）。
   - プログレスバー「印刷準備中...」→「印刷中... (N / Total)」で各シートのビットマップ（300 DPI）を生成し、メモリ内に固定化（`Freeze()`）。
2. **フェーズ2（スプール送信フェーズ）**:
   - シート画像の生成完了と同時に、**印刷プレビューダイアログを即時閉じる**。
   - レンダリング済みのシートデータおよび印刷設定・ジョブ名をバックグラウンド印刷キュー（`BackgroundPrintQueue` / `IPrintService`）へ引き渡す。
   - 独立した専用のバックグラウンド STA スレッドで `FixedDocument` を構築し、`printDialog.PrintDocument(paginator, jobName)` を実行。メインUIスレッドのメッセージループを一切ブロックしない。

### 2.3 ステータスバー表示と複数ジョブのキューイング
- 送信中:
  - 単一ジョブ時: `プリンターへ送信中...`
  - 複数ジョブ時: `プリンターへ送信中... (残り N 件)`
- 送信完了時:
  - `印刷データを送信しました` と約3秒間表示した後、通常のステータス表示（または空白）に自動復帰。
- 送信失敗時:
  - 他のエラー通知と同様に、アプリ内オーバーレイのエラーダイアログ（`ShowErrorDialog`）を表示してエラー内容を明示通知し、ステータスバーを「印刷に失敗しました。」に更新。
- 多重印刷受付:
  - 送信中であってもツールバーの「印刷」ボタンは有効なままとし、新たな印刷操作を開始可能。生成完了したジョブは順次キューに追加され、先行ジョブの完了後に順次スプール送信される。

### 2.4 アプリ終了待機ダイアログ（オーバーレイ）
- 終了トリガー（ウィンドウクローズ `OnClosing`）時の順序:
  1. 未保存の変更がある場合は、既存の「変更内容を保存しますか？」ダイアログを先に表示。キャンセルされた場合は終了自体を取り消す。
  2. 保存／破棄が確定後、送信中の印刷タスクが存在する場合（`HasActivePrintTasks == true`）:
     - ウィンドウクローズを一時保留（`e.Cancel = true`）。
     - アプリ内オーバーレイダイアログ（`IsPrintWaitDialogVisible`）を表示:
       - アイコン・スピナー
       - タイトル: `印刷タスクを実行中`
       - メッセージ: `プリンターへの送信が完了するまで待機しています。完了後に自動的に終了します。`
       - 残りタスク数表示（複数件ある場合）
       - ボタン: `キャンセル`（終了処理を取り消し、待機オーバーレイを閉じて通常のアプリ操作画面へ復帰。印刷処理はバックグラウンドでそのまま継続）
     - 全印刷タスクが完了したら（キャンセルされていない場合）、自動的に `Close()` を呼び出してアプリを終了。

## 4. 検証・品質計画

1. **単体テストの全網羅 (`dotnet test`)**:
   - `PrintJobHelperTests`:
     - 通常のファイル名（`document.pdf` → `document - PDFBinder`）
     - ピリオドが複数あるファイル名（`my.archive.2024.pdf` → `my.archive.2024 - PDFBinder`）
     - 拡張子がないファイル名（`document` → `document - PDFBinder`）
     - 未保存ファイル名（`名称未設定.pdf` → `名称未設定 - PDFBinder`）
     - 空文字・空白・null（→ `名称未設定 - PDFBinder`）
   - `BackgroundPrintQueueServiceTests`:
     - 単一ジョブのエンキューと完了通知
     - 複数ジョブの順次実行と残り件数カウントの遷移
     - ジョブ失敗時のエラーハンドリング
   - `PrintViewModelTests`:
     - ジョブ名が正しく設定されること
     - シート生成完了時にプレビュークローズイベントが発火し、生成済みシートデータが渡されること
   - `MainViewModelTests`:
     - 印刷タスク残存時の `HasActivePrintTasks` 判定
     - 終了待機ダイアログの表示と自動終了シグナル
     - 終了待機ダイアログのキャンセルボタンによるアプリ復帰
     - 印刷失敗時の `ShowErrorDialog` 呼び出し検証
2. **ビルド検証 (`dotnet build`)**:
   - 警告・エラー 0 件の維持。
3. **実機動作確認**:
   - 印刷プレビューから印刷を実行し、生成完了直後にダイアログが閉じ、メイン画面のステータスバーに「プリンターへ送信中...」が表示されること。
   - 送信中もメイン画面が一切固まらず、スムーズに操作可能であること。
   - 送信完了時に「印刷データを送信しました」と約3秒間表示され、自動的に通常表示へ戻ること。
   - 送信中にウィンドウを閉じようとした際、待機オーバーレイが表示され、完了後に自動終了すること。
   - 待機オーバーレイの「キャンセル」をクリックすると、待機ダイアログが閉じてアプリ画面へ戻り、バックグラウンドで印刷が継続すること。
   - 印刷エラー発生時、エラーダイアログが表示されること。
