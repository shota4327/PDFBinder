# CHANGELOG記述方針変更およびGEMINI.mdルール更新の実装計画

## 概要
`CHANGELOG.md` をエンドユーザー（一般利用者）向けのリリースノートとして位置づけ、内部実装の詳細（ファイル名、クラス名、スタイル名、コード上のpx寸法等）を排し、ユーザーから見た機能や操作性の改善点のみをシンプルに記述する方針へ変更します。
あわせて、プロジェクト原則を定めた [`GEMINI.md`](file:///c:/Git/PDFBinder/GEMINI.md) にこの規約を明文化し、今後の開発でも一貫した品質を維持します。

## 決定事項（インタビュー結果）
1. **CHANGELOGの改定範囲**: 今回の `[0.2.0]` だけでなく、既存の `[0.1.0]` も含めて内部実装の詳細を省き、ユーザー視点の簡潔な表現に統一する。
2. **GEMINI.md への反映**: 3.1節（PR運用ルール）および5章（ドキュメント更新ルール）の両方に、エンドユーザー向け・実装詳細除外の厳格な記述方針を明記する。
3. **文面方針**: 内部のスタイル名・クラス名・ファイル名・px指定を完全に排し、何ができるようになったか／どう使いやすくなったかのみを記載する。

## Proposed Changes

### 1. プロジェクト開発原則の更新

#### [MODIFY] [GEMINI.md](file:///c:/Git/PDFBinder/GEMINI.md)
- **3.1節（PR運用ルール）**:
  - `CHANGELOG.md` 確定時のルールとして、「エンドユーザー向けに機能・操作性・改善点のみをシンプルに記述し、内部のファイル名、クラス名、スタイル名、コード寸法（px等）などの開発者向け実装詳細を含めてはならない」旨を追記。
- **5章（ドキュメントおよびルールの自律的・継続的アップデート）**:
  - `CHANGELOG.md` 更新方針として同様の規約を明文化。

---

### 2. リリースノートの改定

#### [MODIFY] [CHANGELOG.md](file:///c:/Git/PDFBinder/CHANGELOG.md)
- **`[0.2.0]`**:
  - 内部クラス名・スタイル名・ファイル名・px指定を削除。
  - バージョン情報画面がメイン画面内のインアプリ表示になったこと、外側クリックで閉じられるようになったこと、ダイアログ全体の見た目が統一されたことを簡潔に記述。
- **`[0.1.0]`**:
  - `Directory.Build.props`, `14pt`, `216 DPI`, `8192px`, `ISFメタデータ`, `GEMINI.md 方式①` などの開発者向け用語を削除・言い換え。
  - 各機能の操作性・ユーザー体験を中心にシンプル化。
