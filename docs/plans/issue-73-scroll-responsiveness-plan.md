# Issue #73 スクロール・ページ送りの反応遅延改善 実装計画

## 概要
詳細エディタの単一ページ表示モード（`SinglePage`）において、マウスホイールを素早く回した際にページの切り替え反応が遅れたり、ホイール入力が間引かれて追従しない問題（Issue #73）を解決します。

### 原因分析
`DetailEditorView.xaml.cs` にて `PageTurnCooldown = TimeSpan.FromMilliseconds(250)` が設定されており、ホイールイベント発生時に前回のページ送りから250ms以内のイベントがすべて破棄（`return false`）されていました。
そのため、ホイールを素早く回転させた際に大部分の回転ノッチが無視され、大きな遅延やカクつき、反応の悪さを引き起こしていました。

---

## 決定事項（インタビュー結果）
1. **対象範囲**: 詳細エディタの「単一ページ表示」モードにおけるホイールページ送り処理。
2. **挙動方式**: 固定待機時間（クールダウン）を撤廃し、**Delta値累積方式（Delta Accumulation）**を採用。回転量（1ノッチ標準値: 120）に達するごとに即座に1ページめくる。
3. **高速回転時**: キーボードショートカット連打と同等の最速レスポンスで、ノッチ数に応じて軽快にパラパラと切り替わるようにする。
4. **端数管理**: 約250msホイール操作が途切れた場合は端数Deltaをリセットし、誤作動を防止する。また逆回転時やページ内スクロール中もDeltaを適切にリセットする。

---

## 変更予定内容

### 1. 新規ヘルパークラスの作成
#### [NEW] `src/PDFBinder.App/Helpers/WheelPageTurnTracker.cs`
- ホイールのDelta累積、タイムアウト判定、ページ送り判定をカプセル化する責務を持つ独立クラス。
- 単体テスト可能（WPF UI非依存）な純粋ロジックとして実装。
- 主な機能:
  - `ProcessScroll(int delta, DateTime timestamp, bool isAtEdge)`
  - 累積値が閾値（120）に達した回数（ページ送り要求数）を返却。
  - 逆方向スクロール検知時のリセット。
  - アイドル時間（250ms）超過時のリセット。
  - 端・境界以外でのリセット。

### 2. ビューの改修
#### [MODIFY] `src/PDFBinder.App/Views/DetailEditorView.xaml.cs`
- 固定クールダウン（`PageTurnCooldown`, `_lastPageTurnTime`）を削除。
- `WheelPageTurnTracker` を利用し、ホイール回転量に応じたページ送りを実行。
- 30〜50行ルールを遵守したクリーンなイベントハンドラへ再構成。

### 3. 単体テストの追加
#### [NEW] `tests/PDFBinder.App.Tests/Helpers/WheelPageTurnTrackerTests.cs`
- 1ノッチ（120 / -120）での正常なページ送り判定テスト。
- 高速連続スクロール（短時間に複数ノッチ）での追従性テスト。
- トラックパッド等の微細Delta（40 + 40 + 40）での累積判定テスト。
- 250msアイドル経過による端数リセットテスト。
- 逆方向スクロール時のリセットテスト。
- ページ端以外（ズームスクロール中）でのリセットテスト。

## 検証計画

### 自動テスト
- `dotnet test tests/PDFBinder.App.Tests/PDFBinder.App.Tests.csproj`
- `dotnet test`（ソリューション全体）

### 手動確認手順
1. アプリを起動し、複数ページのPDFを開いて詳細エディタを表示。
2. 単一ページ表示モード（FitToWindow）にする。
3. マウスホイールをゆっくり1ノッチ回し、確実に1ページ切り替わることを確認。
4. マウスホイールを素早くシュッと回し、回転の勢いに応じて遅延なくパラパラと複数ページめくれることを確認。
5. キーボードの左右キー／PageUp/PageDownキーと同等以上の軽快なレスポンスであることを確認。
6. ページを拡大（Zoom > 100%）した状態で、ページ内スクロールが優先され、上端／下端に達したときのみページ送りが発火することを確認。
